\# Task API



A simple CRUD API for managing tasks, built with FastAPI (Python).



\## What it does



This API lets you create, read, update, and delete tasks. Data is stored in memory, so it resets when the server restarts.



\## How to run it



1\. Clone this repo and go into it: git clone https://github.com/Vusale-Holberton/task-api.git and cd task-api

2\. Create a virtual environment: python -m venv venv

3\. Activate it: venv\\Scripts\\activate

4\. Install dependencies: pip install fastapi uvicorn

5\. Run the server: uvicorn main:app --reload --port 8000

6\. Open your browser at http://localhost:8000



\## Endpoints



GET / - API info

GET /health - Health check

GET /tasks - List all tasks

GET /tasks/{id} - Get a single task

POST /tasks - Create a new task

PUT /tasks/{id} - Update a task

DELETE /tasks/{id} - Delete a task



\## Example usage



curl -i http://localhost:8000/tasks



Response: HTTP/1.1 200 OK and a JSON list of tasks.



\## Interactive docs (Swagger UI)



FastAPI automatically generates interactive docs at http://localhost:8000/docs where you can try out every endpoint in the browser. See swagger-screenshot.png in this repo.

\## AI vs me



I compared my hand-written CRUD API against a version generated by AI from my own prompt.



What the AI did better: it used separate Pydantic models (Task, TaskCreate, TaskUpdate) for cleaner structure, and added a proper API title.



What I missed: I didn't specify status codes clearly enough in my prompt, so the AI's POST /tasks returned 200 instead of the correct 201 Created that my own version used.



What my prompt forgot to clarify: I didn't mention the / and /health endpoints, or ask for specific HTTP status codes for each action, so the AI had no way to know I wanted those.
